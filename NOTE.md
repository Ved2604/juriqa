# Submission note

**How quote verification works, and where it could fail.** Instead of matching quotes as strings, I changed the problem. Documents are split into passages of 50–150 words along clause boundaries, each with an ID. The model cites IDs, and the app displays the stored passage text, so the model never types a quote and cannot paraphrase or invent one. Every cited ID is checked against the passages the model was actually given during that answer. Anything else is struck through and flagged as unverified. Positions and pages come from the stored passage, not the model. This avoids whitespace false-negatives entirely. Where it can still fail:
- It proves a passage is real and was read, not that it supports the sentence citing it. The model could cite a real but irrelevant passage.
- Text-extraction errors in a messy PDF (columns, tables) would be faithfully "verified", because the stored text itself is wrong.
- Highlighting works per line, so a passage that starts mid-line highlights slightly too much.

**How I handled large documents.** Code tracks which passages were sent to the model for each answer, and every answer shows a coverage badge. "It isn't in the document" is only allowed after a full read. If the model concludes something is missing from targeted searches alone, the app discards that draft, reads every passage in parallel batches (a 150-page contract takes about 10 seconds; each batch returns only passage IDs), and answers again. Summary and "list all" questions read the whole document first. A failed batch is recorded, and the answer names the unread pages.

**Part C: option 2, agentic research.** I chose it because it is also the large-document strategy. Targeted tool calls scale to 150 pages without pushing the whole document into the prompt, and the tool trace doubles as the live progress display. It is complete: a multi-round loop with five tools, a 6-round cap, malformed and invented calls returned to the model as errors, live status, and verified citations on the final answer. The hardest part was making the model's claims trustworthy. It ignored prompt instructions in practice: it cited table-of-contents IDs it had never read, and skipped the full read for summaries. So the important rules became code, not prompts: citation checks, a full-read requirement before "not found", and a router-forced full read for summaries.

**What I would build next.** Clause numbers from Word's automatic numbering. Sub-line highlighting of the exact sentence, using a verified excerpt within the cited passage. Testing on a corpus of real contracts with complex layouts. A check that each cited passage actually supports its claim. Then accounts with private storage.
